# Import the Reference Catalog through ordered Import Sets

The original Skills and Certificates workbooks are authoritative bulk inputs, so they land in separate staging tables and reach Skill and Certificate through Transform Maps rather than direct target writes. The nine canonical Product Lines are deployed first as source-controlled reference records because the workbooks use only eight of them and cannot produce Nonstop Cloud. Both reference maps resolve Product Line by `name` and reject unknown values. Before the first import, the evaluation instance receives a one-time full application data reset in dependency order: Submissions first so their children cascade, any orphan Cert Acquisitions and Skill Assessments, then Certificates, Skills, and Product Lines; Levels, groups, roles, ACLs, modules, and ATF metadata remain. Demo seed definitions are reconciled before redeploy so deleted non-authoritative rows do not return. After that reset, re-runs are upserts: Skill and Certificate coalesce on their Product Line plus description/name, backed by matching unique target indexes. Routine imports never delete rows omitted from a later workbook; later removals require an explicit migration.
